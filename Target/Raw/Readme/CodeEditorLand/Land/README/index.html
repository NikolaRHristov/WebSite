Land 🏞️ — The Next-Generation Code Editor

Welcome to Land! We are building a high-performance, resource-efficient, cross-platform code editor inspired by the best of VS Code. Land is engineered with a modern stack – Rust and Tauri for its core – to deliver a lightning-fast, memory-conscious, and deeply familiar editing experience for developers.

Our vision is to create a truly adaptable editor that not only matches VS Code’s core functionality but also offers a flexible foundation for running extensions in various environments, optimizing for performance, security, and specific use cases.

Our Journey: Phased Evolution 🗺️

Land’s development is a phased journey towards this vision:

  1. MVP Path A (Current Focus): Establish a functional core editor with a Node.js sidecar (Cocoon) to run existing VS Code extensions. This allows us to leverage the vast VS Code extension ecosystem quickly while benefiting from Tauri’s native performance for the main application.
  2. MVP Path B (Future Goal): Develop a Rust-native extension host (Grove). This aims to provide a highly optimized, secure, and performant environment for extensions, potentially enabling extensions written in Rust or WASM.
  3. Exploring Alternative Runtimes (Future Research): Investigate and potentially support other lightweight JavaScript runtimes for specialized extension sidecars, such as Deno or LLRT (Low Latency Runtime), for scenarios where their unique benefits (security, startup speed) are paramount.

This README primarily details the current MVP Path A architecture, with an eye towards these future evolutions.

Core Architecture Principles 🏗️

No matter the extension host flavor, Land’s core architecture is designed for modularity and performance:

ComponentRole & Key ResponsibilitiesPrimary Technologies
MountainThe native Rust/Tauri backend. Manages the app lifecycle, native OS operations, UI windows (via Tauri), the Track command dispatcher, and Vine IPC for communication with any sidecar extension hosts.Rust, Tauri
SkyThe user interface, built with Astro and web technologies, running in Tauri’s native webview. Reuses VS Code UI components for a familiar experience. Interacts with Mountain via the Echo API contract.Astro, JS/TS, HTML/CSS
EchoThe API contract defining actions and data structures for Sky <-> Mountain communication.Rust
TrackMountain’s central command dispatcher, routing Echo actions and sidecar RPC requests.Rust
VineThe primary IPC layer (stdio JSON) for Mountain to communicate with any sidecar-based extension host (Cocoon, potential Deno/LLRT sidecars, or a process-isolated Grove).Rust (Mountain), JS (Sidecar)
River/SunNative Rust libraries for efficient, asynchronous filesystem read (River) and write (Sun) operations, used by Mountain.Rust

Current Focus: MVP Path A - The Cocoon (Node.js Sidecar) Cocoon 🦋

Our immediate goal is to deliver a functional Land editor by running existing VS Code extensions within Cocoon, a dedicated Node.js sidecar process.

Cocoon Architecture:

Component within Path ARole
Cocoon ProcessA Node.js process launched by Mountain. Hosts VS Code’s ExtHostExtensionService using pre-bundled platform code.
Shims (in Cocoon)JavaScript modules mimicking VS Code’s ExtHost* services. They intercept API calls from extensions and proxy them to Mountain via Vine IPC for native execution or UI updates.
Rest (JS Bundler)A build-time process (esbuild/webpack) that bundles necessary VS Code platform JavaScript into a CommonJS format that Cocoon can load and execute.

How it Works (Simplified):

  1. Mountain launches Cocoon.
  2. Cocoon initializes, loads the bundled VS Code platform code and ExtHostExtensionService.
  3. An extension in Cocoon calls a vscode.* API (e.g., vscode.workspace.fs.readFile).
  4. A Shim in Cocoon intercepts this call.
  5. The Shim sends a request via Vine (JSON over stdio) to Mountain.
  6. Mountain’s Track dispatcher routes this to the appropriate Rust handler (e.g., using River to read the file).
  7. Mountain sends the result back to Cocoon via Vine.
  8. The Shim returns the result to the extension.

This approach aims for high compatibility with existing Node.js-based VS Code extensions by providing them with a familiar Node.js environment and shimming the APIs they expect.

Future Extension Host Paths & Feature Parity 🚀

While Cocoon (Node.js sidecar) is our Path A for MVP, Land is designed with future flexibility in mind to achieve greater performance, security, and potentially support different classes of extensions.

Path B: Grove - The Native Rust Extension Host 🌳

  • Concept: A complete rewrite of the VS Code extension host logic in Rust. Grove aims to run extensions (potentially those recompiled to WASM or new extensions written in Rust/WASM) in a highly performant and secure native environment.
  • Goal: Drastically reduce the overhead associated with a Node.js runtime, improve security through Rust’s safety features and potential WASM sandboxing, and enable deeper integration with Mountain.
  • Status: A longer-term vision. This would involve reimplementing the entire vscode.* API surface in Rust.

Alternative Runtimes (Conceptual Exploration) 🧪

  • Deno Sidecar: Explore using Deno as an alternative sidecar runtime. Deno’s focus on security, TypeScript-first approach, and different module system could offer benefits for a specific class of extensions. Communication would still likely be via Vine.
  • LLRT Sidecar: Investigate using LLRT (Low Latency Runtime - QuickJS based) as an ultra-lightweight sidecar for extensions that fit its specific Node.js API subset and performance profile (fast startup, suitable for smaller, event-driven tasks).

Achieving Feature Parity: Our long-term ambition is to achieve a high degree of feature parity with VS Code. This will be an iterative process:

  1. Core Editing & MVP Extensions (Path A): Ensuring basic text editing, file management, and core extension APIs function reliably via Cocoon.
  2. Expanding API Coverage (Path A/B): Incrementally implementing more shims (Path A) or native API implementations (Path B - Grove) to support a wider range of extensions.
  3. Native Feature Implementation: Re-implementing complex VS Code features (Debugging, SCM, Tasks, Rich UI Panels) natively in Mountain and Sky.
  4. Performance & Stability: Continuously optimizing all components.

(Tracking feature parity is a manual process involving extensive testing and comparison against VS Code, not an automated code analysis.)

Getting Started 🚀

1. Clone the Repository:

git clone ssh://git@github.com/CodeEditorLand/Land.git --recurse-submodules

2. Install Dependencies:

pnpm install

3. Build the Application:

Our build process prepares VS Code dependencies, bundles JavaScript for Cocoon, compiles Rust, and builds the Tauri application.

Build Variables Explained:

VariablePurpose
Browser=trueInfluences JS build targets (web compatibility).
Bundle=trueCrucial for Path A! Triggers bundling of VS Code platform JS for Cocoon.
Clean=trueClears previous build artifacts for a fresh build.
Dependency=Microsoft/VSCodeSpecifies the VS Code source/version for Cocoon’s JS bundle.
NODE_ENV=development or productionControls build optimizations (minification, debug info).
NODE_OPTIONS=--max-old-space-size=16384Increases Node.js memory for resource-intensive bundling.

Development Build:

pnpm cross-env Browser=true Bundle=true Clean=true Dependency=Microsoft/VSCode NODE_ENV=development NODE_OPTIONS=--max-old-space-size=16384 pnpm tauri build

Production Build (Release):

pnpm cross-env Browser=true Bundle=true Clean=true Dependency=Microsoft/VSCode NODE_ENV=production NODE_OPTIONS=--max-old-space-size=16384 pnpm tauri build --release

4. Run Land:

Development Mode: (Includes frontend hot-reloading)

pnpm run tauri dev

Production Build: Find the executable in Element/Mountain/target/release/ (or a bundle subdirectory).

Usage Guide 🛠️

When you run Land:

  1. Mountain (the Tauri app) starts up.
  2. For Path A, Mountain automatically launches the Cocoon Node.js sidecar.
  3. The Sky UI loads in the Tauri webview.
  4. The MVP aims to load a “Hello World” extension, demonstrating core functionality.
